# Decisions worth retaining

This is a compact record of consequential choices and their reasons. Current
rules live in the linked guides and code; routine changes belong in Git/PRs.
IDs remain stable for asset records. Superseded detail is recoverable from Git
history before the documentation consolidation (`7172c1e`).

| ADR | Decision and reason |
| --- | --- |
| 0001 | Godot 4.7.1 .NET, Forward+, Windows first: one supported desktop baseline. |
| 0002 | C# with a pure `net8.0` core: fast rule tests and shared CLI/game behavior. Supersedes the removed GDScript spike. |
| 0003 | An authored station POC before procedural runs: establish an enjoyable, reproducible loop first. The original 8–12 minute/two-fight scope is expanded by 0031. |
| 0004 | Typed commands, atomic validation, stable IDs, explicit 30 Hz ticks: consistent human and automated control. |
| 0005 | Authored dialogue on the POC critical path: no runtime model dependency. Optional local experiments use supported Codex CLI access, never scraped sessions or distributed developer credentials. |
| 0006 | Blender editable sources → validated GLB → Godot review: replaceable providers and reproducible publication. Implemented through the current art pipeline. |
| 0007 | Separate branches/worktrees for concurrent implementation, isolated Godot state, one owner for shared contracts/assets. The current single-agent exception is 0027. |
| 0008 | Rule, CLI, engine, and graphical verification answer different questions; none substitutes for a required higher layer. |
| 0009 | Validated text gameplay content joined to authored Godot spatial scenes: rules remain usable outside the engine. Revisit authoring ergonomics only when they become a demonstrated bottleneck. |
| 0010 | One current action and one replaceable pending order; explicit-target repeating attacks with player-directed abilities. Keeps tactical control bounded; refined by 0027. |
| 0011 | Future dialogue profiles select model, reasoning, and Fast mode independently; coherence precedes latency. Settings remain outside gameplay state. |
| 0012 | Automatic pause on combat entry, otherwise manual combat control. Amended by 0026 to pause on defeat for retry; no auto-pause for ordinary threats/cooldowns. |
| 0013 | Future free-text dialogue is the player's exact utterance; neither rewriting it nor treating it as authoritative world state is allowed. |
| 0014 | Handheld, integrated, and body attacks share core authority. Animation and physical presentation cannot resolve hits or damage. |
| 0015 | One fixed runtime outfit per human; editable undersuit/armor pieces support future whole-outfit variants without an equipment system. Complete topology work before rigging. |
| 0016 | Owner-approved humanoid pipeline (2026-08-02, amended Aug 3–4): T-pose → Tripo Quad-10k → validated Mixamo → Blender repair. Prevent repeat rig/rest-pose failures. Matching-with-skin donor exceptions require recorded evidence; routine provider steps need no repeated confirmation. |
| 0021 | Owner-approved ship experiment (2026-07-29) follows station POC hardening. The separated overhead composition is a direction reference, not authorization for final combat interiors, enemy-ship assets, or a larger ship system. Station departure and milestone sequencing are amended by 0031. |
| 0022 | Enforcer melee plus rigid sentry ranged pressure replaces the ram drone (2026-08-02; bases approved Aug 7): two distinct threats without bespoke non-humanoid locomotion. |
| 0023 | Static station production advanced to Phase 3 (2026-08-02): dimensionally authored Blender modules over independent Godot spatial wrappers. |
| 0024 | Solo fight before Protector recruitment (2026-08-04); Vanguard is fixed. Operator's original deferral is superseded by 0031. Reviewed production presentation covers the active route before combat; fight animation is finalized with gameplay timing. |
| 0025 | Two authoritative service-door gates in the five-area route (2026-08-04): navigation availability and approach-triggered completion stay observable. The original locked solo exit was advanced by 0026. |
| 0026 | Bounded solo encounter (2026-08-08): Vanguard/Enforcer, suppression, one-charge aid, defeat pause, isolated retry, victory exit, recruitment. Damage uses numbers/effects without hit-reaction clips. Timing/handling recipe superseded by 0027. |
| 0027 | Repair the solo slice before expanding (owner-approved 2026-09-06): preserve attack intent through abilities/aid, prevent click/replacement exploits, and allow authored handling plus procedural aim/IK/recoil. Use bounded graphical input/motion checks and separate real-time performance measurement. The owner explicitly chose the existing checkout for gameplay and art. |
| 0028 | After owner solo acceptance (2026-09-07), extend the same command/action model to two crew and two hostiles, with independent orders and nonrecursive Guard damage sharing. Guard may replace offensive recovery presentation without erasing its deadline. Include the focused party HUD in this slice so coordination can be playtested before final-route work. Guard superseded by 0029. |
| 0029 | Owner playtest feedback (2026-09-08): explicit target orders and two skills per role keep combat deliberate; remove idle automatic fire and Field Aid. Vanguard uses Interrupt/Burst and Protector Barrier/Taunt. The owner's revised Barrier direction is ground placement with an independent facing, fixed after deployment. Sentry flight/interception belongs to fixed-tick core rules so deployment can stop a flying shot; crew bolt travel stays cosmetic. Total defeat permits bounded presentation settling to finish the crew fall before retry. |
| 0030 | Owner control simplification (2026-09-09): remove manual Face Direction, its queued action and heading lock, and its input/automation entry points. Crew retain automatic body turning; Barrier placement retains its independent fixed direction. Adapter schema 9 removes the manual-facing command and observation fields. |
| 0031 | Owner-approved station escape expansion (2026-09-12): recruit Operator as Medic after the two-person encounter, add four connected multi-enemy fights and a mobile rifle Enforcer, then board and depart in the cutter. Three independent crew with player-commanded Heal/Healing Field extend the existing typed command model. Ordered encounters, victory recovery, and isolated retry keep the larger route bounded without a quest framework; content/automation advance together to schema 10. Approved Operator/pistol sources, the existing Enforcer/carbine designs, station kit, and cutter exterior support production. Fold station hardening into Phase 5's owner/full-route gate and make three-crew ship combat Phase 6, the next gameplay milestone. No ship interior or ship-combat rules enter this station expansion. |
| 0032 | Shared crew vision (2026-09-22) separates player perception from diagnostic encounter state. Pure core rules evaluate content-owned sight settings against immutable full wall/door bounds; camera cutaway cannot reveal enemies. Dormant discovery and loss of sight affect presentation and target eligibility without changing authored encounter triggers. Content/automation schema 11 exposes visible hostiles and each hostile's encounter/facing metadata. See [Architecture](ARCHITECTURE.md#shared-crew-vision) for the current rules; stealth and vision cones remain outside scope. |
| 0033 | Ship battle scope expansion (user request, 2026-09-24) supersedes the older no-fire/no-oxygen ship scope: manning, fires, hull breaches, per-room oxygen, controllable doors and a manual vent airlock, four powered player systems including targetable life support, Medic treatment instead of a medbay, an unmanned enemy with finite visible repairs, authored enemy target/payload sequences, no boarding, and downed crew restored on victory. Pure `ShipCombatSession` and content `ship-battle.json` own the rules; the Godot host is a separate scene entered once after station departure. Owner handling/tuning acceptance is open. See the [ship spec](future/ship-combat-poc.md). |
| 0034 | FTL-style ship rework (owner request, 2026-09-25) keeps ADR 0033's hazards and handoff but amends its combat: each side mounts weapons that draw weapons-system power in mounting order, charge and target independently, and can be held for a synchronized volley; missiles pierce shields, never miss and use finite ammunition; hits damage the target system by weapon damage and injure crew in the room; the Medic auto-treats in the current room. Engines give evasion instead of slowing enemy charge, so random rolls are now allowed, only from one seeded stream per attempt so a seed, attempt and command log replay exactly (superseding 0033's no-random-rolls). The interceptor is rebuilt roof-off with three targetable rooms; shields read as layer pips and a bubble, never as room damage or percent. The whole game uses a sampled CC0 cue library (no music yet) with pinned sources and per-take provenance instead of synthesized cues. Owner acceptance is open. See the [ship spec](future/ship-combat-poc.md). |
| 0035 | Seamless station encounters (owner request, 2026-09-26) supersede the entry-zone start of 0012, 0031 and 0032: a fight starts when a living hostile of the next encounter in authored order sees a living recruited crew member within `vision.hostile_detection_meters` (shorter than crew sight, 360°, walls and closed doors block; no cones or stealth), its whole encounter alerts, and the game auto-pauses where everyone stands, with no crew repositioning or camera snap. The route objective still orders fights. Retry restores the crew positions and headings captured at that moment instead of authored restart spots. Content/automation move to schema 12 (detection range; spotter and spotted crew on the encounter and its start event). See [Architecture](ARCHITECTURE.md#encounter-flow). |
